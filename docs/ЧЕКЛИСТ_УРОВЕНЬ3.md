```bash

curl -s -X POST $GW/core/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"t3@example.com","password":"Test1234","name":"Тест"}'

  -H 'Content-Type: application/json' \
  -d '{"email":"t3@example.com","password":"Test1234"}' | jq -r .accessToken)
```

## 🐞 Баги, найденные на уровне 3 (и исправленные)

Автотесты уровней 1–2 их не ловили, т.к. оба относятся к bootstrap-механизмам gateway, минующим тестируемый код.

1. **Per-service префикс в generic-прокси** (`proxy.controller.ts`).
   `extractPath()` срезал `/api` для всех сервисов одинаково, но core-svc поднят с `globalPrefix('api')` и ждёт путь с `/api`, а taxi/ai — без. Итог: `POST /api/core/auth/register` → `Cannot POST /auth/register` (404).
   **Фикс:** карта `UPSTREAM_PREFIX = { core: '/api', taxi: '', ai: '' }` — префикс upstream подставляется по сервису.

2. **Multipart raw-proxy терял путь** (`main.ts`).
   При строковом `app.use('/api/core/profile/me/avatar', proxy)` Express обрезает mount-путь, и `http-proxy-middleware` видит `req.url === '/'`; строковый `pathRewrite` по `req.url` не срабатывал → `Cannot POST /`.
   **Фикс:** `pathRewrite` переведён в функцию, переписывающую путь по полному `req.originalUrl` (для avatar, картинки новости и AI-speech).
